# NikeAppIOS

## 📱 О проекте

**NikeAppIOS** — iOS-приложение, разработанное на **SwiftUI**, имитирующее e-commerce приложение бренда Nike. Проект ориентирован на демонстрацию архитектурного подхода, работы с состояниями, асинхронностью и интеграции с собственным backend.

Приложение использует современный стек iOS-разработки, масштабируемую архитектуру и реальный клиент-серверный сценарий.

---

## 🧠 Архитектура и подходы

Проект построен с использованием **MVVM** и state-driven подхода SwiftUI:

* Разделение UI, бизнес-логики и состояния
* Использование `ObservableObject`, `@State`, `@Published`, `@EnvironmentObject`
* Централизованное управление состоянием приложения
* Отказ от MVC в пользу декларативной архитектуры

Навигация и взаимодействие экранов реализованы через SwiftUI (`NavigationStack`, `TabView`, `fullScreenCover`, `sheet`).

---

## ⚙️ Конфигурация и окружения

Для управления окружениями используется связка:

* `.xcconfig` (Debug / Release)
* автоматически генерируемый `Info.plist`
* пользовательские build-переменные

### 🔑 API_BASE_URL

Подключение к backend осуществляется через переменную окружения `API_BASE_URL`, которая:

* объявлена в `Debug.xcconfig` и `Release.xcconfig`
* пробрасывается в `Info.plist`
* читается в коде через `Bundle.main`

Пример:

```xcconfig
API_BASE_URL = https://holocrine-hedwig-lathlike.ngrok-free.dev
```

Это позволяет:

* легко менять backend без изменения кода
* разделять Debug / Release окружения
* использовать production-подход к конфигурации

---

## 🌐 Backend

Проект подключён к **собственному backend на Go**, развернутому локально и опубликованному через **ngrok**.

* Backend находится в отдельном репозитории: **`backend-NikeAppIOS`**
* Используется реальный HTTP API
* Изображения и данные подгружаются с сервера

Такой подход демонстрирует понимание полного клиент-серверного цикла.

---

## 🔄 Работа с данными

В проекте активно используются:

* модели данных для товаров, избранного и корзины
* коллекции (`List`, `ScrollView`, `LazyVGrid`)
* уникальные идентификаторы (`UUID`)
* локальное хранилище (`UserDefaults`) для сохранения состояния

Это позволяет управлять списками, состояниями и пользовательскими действиями в реальном времени.

---

## 🧵 Многопоточность

Многопоточность применяется для:

* отложенных действий (Splash Screen)
* анимаций и UI-обновлений
* корректного выполнения операций в main thread

Используются:

* `DispatchQueue.main`
* асинхронные вызовы с таймингами

UI всегда обновляется в главном потоке, что соответствует требованиям iOS.

---

## 🎨 UI и анимации

Проект содержит:

* сложные кастомные экраны
* анимации добавления товара в корзину (fly-to-bag)
* state-driven UI
* адаптивную вёрстку под разные размеры экранов

Весь интерфейс реализован на **SwiftUI** без Storyboard.

---

## 🧩 Dependency Injection

Зависимости передаются через:

* `@EnvironmentObject`
* инициализацию state-объектов на уровне приложения

Это упрощает тестирование, масштабирование и повторное использование компонентов.
